# Internals

For whoever changes Origo. The pages one level up are written for
people who run Origo or call it; these describe how it works inside and
how a change is proved.

| Page | |
|---|---|
| [Architecture](architecture.md) | the code map, what the bucket holds, and how a push, a read, compaction, placement, events, and a storage outage move through the packages |
| [Testing](testing.md) | the test tiers, what each proves, what it needs, and how to run it locally |
| [Releasing](releasing.md) | the changelog rule, cutting a version, what the release workflow builds and proves, and publishing from a fork |
| [Contract reference](contract.md) | every endpoint, header, and error code as the design specs define it, with the implementation detail behind each row. Generated by `make docs` |

The design records are in [`specs/`](../../specs/README.md), one per
module or decision, each with the alternatives it weighed and an
Outcome recording what was built. Start with
[`001-architecture`](../../specs/001-architecture.md), which states the
invariants the others are held to. [`CONTRIBUTING.md`](../../CONTRIBUTING.md)
is how to send a change.
