# Git LFS

## Overview

Large files belong in object storage, not in packs. Origo implements the
LFS batch API and hands clients presigned URLs so bytes never pass
through a node.

## Current state

Spec 001 reserves `origo/repos/<id>/lfs/<oid>`.

## Design

`POST /<owner>/<slug>.git/info/lfs/objects/batch` with the standard body;
`download` returns a presigned GET per object (15 minutes), `upload`
returns a presigned PUT with `Content-Length` pinned and a `verify`
action; `verify` checks that the object exists with the declared size and
records it in the repository's LFS manifest object. Objects are content
addressed by their `oid`; a repository's manifest lists what it references
so deletion and quota work per repository while identical objects are
stored once per repository (no cross-repository dedup in v1).

Authorization is `read` for download and `write` for upload through the
authorizer. Sizes count toward the repository quota. Locks
(`/locks`) are not implemented and answer 501.

## Acceptance criteria

- `git lfs push` and `git lfs fetch` round-trip a 500 MiB file through
  MinIO with the node's own transfer under 1 MiB.
- An upload whose size differs from the declaration is rejected at verify.
- Deleting the repository removes its LFS objects after the hold.
