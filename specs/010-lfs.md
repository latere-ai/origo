# Git LFS

## Overview

Large files belong in object storage, not in packs. Origo implements the
LFS batch API and hands clients presigned URLs so bytes never pass
through a node.

## Current state

Spec 001 reserves `origo/repos/<id>/lfs/`. `latere.ai/x/pkg/s3` has
`PresignGet(key, expires)` and `PresignPut(key, expires, contentLength)`.
`internal/lfs` does not exist and no route under `info/lfs` is served.

## Design

### Endpoints

`{repo}` is `r/{id}.git` or `{owner}/{slug}.git` as in spec 003.
Requests and responses are `application/vnd.git-lfs+json` in the shape
the LFS batch API fixes.

| Method | Path | Behaviour |
|---|---|---|
| POST | `/{repo}/info/lfs/objects/batch` | `{"operation": "download"\|"upload", "objects": [{"oid", "size"}], "transfers": ["basic"]}`; action `read` for download, `write` for upload; answers one action per object |
| POST | `/{repo}/info/lfs/verify` | the `verify` action of an upload: `{"oid", "size"}`; 200 when the object exists with that size, 422 otherwise |
| POST | `/{repo}/info/lfs/locks` | 501; every path under `locks` answers 501 |

### Objects

| Key | Content |
|---|---|
| `origo/repos/<id>/lfs/<oid>` | the object bytes, written by the client through the presigned `PUT` |
| `origo/repos/<id>/lfs/verified/<oid>` | `{"size", "at", "subject"}`, created by `verify` with `If-None-Match: *`; an existing marker is a success |

A `download` action is a presigned `GET` on `lfs/<oid>` valid 15
minutes, given only when `lfs/verified/<oid>` exists; otherwise the
object's `error` is 404. An `upload` action is a presigned `PUT` on
`lfs/<oid>` valid 15 minutes with `Content-Length` pinned to `size`,
plus a `verify` action naming the endpoint above with the request's
token. Objects are content addressed by `oid`; identical objects are
stored once per repository and not across repositories. Presigned URLs
are signed against `ORIGO_S3_PUBLIC_ENDPOINT`, the bucket endpoint LFS
clients can reach, which defaults to `ORIGO_S3_ENDPOINT`.

### Errors

The batch API carries its own error shape: a top-level failure is the
HTTP status with `{"message": "<sentence>"}`, a per-object failure is
`"error": {"code": <status>, "message"}`. The sentences are the ones of
spec 003's table for the matching code: 401 `unauthenticated`, 403
`forbidden`, 404 `repo_not_found`, 413 `over_quota`, 429 `rate_limited`,
503 `storage_unavailable`; the envelope is not used on these paths.

### Quota

Before answering an `upload` batch the node lists `lfs/verified/` once
(paged by 1 000) and sums the sizes; when `size_bytes` of the newest
index plus that sum plus the batch's sizes exceeds the authorizer's
`quota_bytes` (spec 012), the batch is 413 `over_quota` with
`details.limit: "repository"`. `verify` with a size that differs from
the stored object's answers 422 and deletes the object.

### Deletion

The purge of spec 004 removes `lfs/` with the rest of the prefix after
the hold. Spec 019's `stats` reports `lfs_bytes`.

## Not in this spec

Locks. Cross-repository deduplication. The `ssh` and multipart
transfer adapters. Garbage collection of uploaded objects never verified
(spec 019's orphan sweep).

## Acceptance criteria

- `git lfs push` and `git lfs fetch` round-trip a 500 MiB file through
  MinIO while the node's public listener receives under 1 MiB of request
  bytes, measured by a counting listener in the test (proposed:
  `test/e2e`, `TestLFSRoundTripBypassesTheNode`).
- An upload whose stored size differs from the declared size is refused
  at `verify` with 422 and the object is deleted (proposed:
  `internal/lfs`, `TestVerifyRefusesASizeMismatch`).
- A download batch for an oid without a `verified` marker answers a
  per-object 404 and one with the marker answers a presigned URL that
  serves the bytes (proposed: `internal/lfs`, `TestDownloadNeedsVerification`).
- An upload batch that would exceed `quota_bytes` answers 413 with the
  `over_quota` sentence (proposed: `internal/lfs`, `TestUploadOverQuota`).
- Deleting the repository removes `lfs/` after the hold
  (`internal/wal`, `TestSweepRemovesOrphansAndKeepsWhatAnIndexNames`,
  extended with an LFS key).
- Every path under `locks` answers 501 (proposed: `internal/lfs`, `TestLocksAre501`).
